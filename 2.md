--- Action Logic

- Each `action` defines 4 methods
    - ActionLogic
    - ActionInput
    - GetId
    - SetId
- The ActionLogic returns a function that takes `ActionInput` and `QueryResult` as parameters and returns a `Task`
- The ActionInput returns a function that deserializes an `ActionInput` object from a Dictionary
- `GetId` and `SetId` are for the `ActionManager` to set a unique Id for each `action` upon registration
- When registered in the `ActionManager`:
    - `ActionManger` maintains a list of all registered `actions`
    - The Id for each `action` is their index in the list
    - At the list index, the `ActionLogic` and `ActionInput` are stored
    - When called via RPC, the `ActionManager` will:
        - Lookup the provided Id
        - Use the `ActionInput` function to parse the parameters
        - Fulfill the `Query` required by the `action`
        - Pass the `QueryResult` and `ActionInput` to the `ActionLogic`

--- Game Loop

- The game has 2 threads
    - The UI thread handles the user input and UI interaction
    - The Game thread handles the action resolution and world state update
- UI Thread
    - Composed of UI System Managers
        - These are groups of UI that perform a uniform task
        - They accept a `QueryResult`
        - Then call all underlying units to process
- Game Thread
    - Processes any queued `Actions`
    - Processes all `Entities`
- Game Manager
    - Starts Game Thread then just lets it go
    - Kicks off UI Thread on `Process`

- World processing idea
    - Input is processed very rapidly and things happen instantly
    - However, game and its consequences only run during a tick
        - Basically, you can move and attack, but no collision is checked until a tick
        - The game does not display this (no visual for [character moved])
        - Attacks occur and enemies take damage, but the visual for it is delayed until the tick
            - Everything else acts on the tick or some multiple
        - Collision checks on the tick; it checks "where are you" during the tick, even though you can still move when it isn't the tick
        - Actions that affect you occur, but actions that affect other people only happen on the tick
    - The game thread runs on a loop
        - If the current iteration is during a "tick", then run some extra actions to resolve positions, damage, etc
            - Collisions might just take care of everything
                - "Collide" with spell -> handle result
                - "Collide" with weapon -> handle result
                - "Collide" with another creature -> move back to last known position
- Action Sync
    - Clients send their desired actions to the server
    - The server collects and queues the actions
    - When a tick occurs on the server, it sends all the collected & validated actions to all clients
    - Clients execute actions to update world state

- Game flow
    - Game split up into levels of varying difficulty
    - You can go to the levels in any order, but levels are connected in a map
    - If you enter a room, the difficulty rises
        - If you re-enter a room, the difficulty rises more significantly
    - You need to get to the boss to stop the difficulty from rising too high
    - If you go to every room inefficiently, the difficulty rises too high
    - If you go to too few rooms, you don't get enough power to outpace the curve
    - If you go to as many rooms as you can as efficiently as possible, you win
    - The goal of the game encourages playing it in the most optimal way

---- Game Lore

Each "black hole" of a universe is what gives birth to the higher dimension. In the 3rd dimension, each black hole is actually the start of a 4th dimension universe. The reason light stops there is because it is being taken into the higher dimension, like if you had a 2-dimensional "hole". The "hole" is where the new dimension appears and a universe is created for it, starting their "big bang".

Time is the fourth dimension, because it is created by the 4th dimension and measures how far you are from the origin of the 4th dimension (the "big bang"), the origin of the 4th is also the "grid" origin of the 1st, 2nd and 3rd.

Likewise, our current 3rd dimensional universe is created from a similar "black hole" in a different, 2nd dimensional universe.

---

Big bang is the beginning of time, black hole is the end of time. Our distance from big bang is how old we are, and distance to the black hole is how old we are yet to be, and position in that is the position of the remainder of your dimensions. The black holes different distances from matter in the universe just represent the different ages of all things, which explains why all living things die (they are just repeating a property of what they are built with). Escaping the inevitable event horizon means that thing lives forever, but all we can see is the apparent event horizon so we don't know where we need to go to in order to do that.

---- Mechanics

- Quantum Marbles
    - Each player gets the same set of marbles at the start of the turn
    - They each make a shot against the marbles
    - The average of each marbles' points is used after all players make their shots
    - Single player where each marble takes a shot with the same physics convention
    - Once player has shot all their marbles, that's the round
    - Goal is to score as many points as possible
        - Also opportunity to score money
        - Money used in shops to buy upgrades
            - Brotato style where you can just roll endlessly
        - Marble slots can be upgraded with the shop
        - Also can buy more marbles/upgrades at shop
    - Points are bounces
    - Bounce points can increase further into the bounce chain
    - Upgrades are applied in an order
        - User can live reorder to adjust the bonus order as it's being applied
            - Will speed up over time to make this harder to do infinitely
    - Can upgrade marbles or number of marble slots

- Spellcasting marble:
    - You imbue a sequence into the marbles
    - When bounced, the marbles iterate up in the sequence
    - Marbles with the same sequence iterate together
    - When everything is settled, all sequences combine into a spell (or more?)

- Variants of power ups
    - Scoring: Lets you score lots of points to get past rounds/do the thing now
    - Scaling: Lets you improve your points a little now, but for long-term payoff
    - Money: Lets you earn more money to then spend on scoring or scaling

- Scoring goes up to int.max
    - Above that, it will read infinity or NaN or whatever
    - In reality, this rolled us into a new counting system, where NaN is 1
    - We have another variable counting how many NaN's we hit
    - Once our score requirement is NaN, it now must be greater than that threshold to pass
        - Since each NaN is 1, and in between doesn't count (round down), we need 2 NaN to continue
        - And we can actually do that if we manage to score 2 NaN by the time NaN becomes a score requirement
